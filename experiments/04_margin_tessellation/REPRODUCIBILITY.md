# Reproducing the saved-scene diagnostics

This update is a completed set of **diagnostic studies in an unfinished
research project**. Publishing the code and results does not mean that
the continuum topology, global L0 accuracy, or margin GMF proof is complete.
The unresolved results are part of the evidence being preserved.

The publication set includes the scripts and tests, these reports, and the
five saved result folders' CSV, JSON, Markdown, PNG, and NPZ files. The
original edge run is retained alongside its refined successor; its lone
unstable reference must not be silently relabelled as stable.

The NPZ files are useful research evidence: they retain sampled profiles,
original component values on patch nodes, direct patch samples, and refined
interpolation results. In particular, the follow-up can be repeated using
the saved patch NPZ files without the original full-domain VTI scene.
Individual NPZ archives are about 0.7–1.3 MB. The largest new CSV is the
approximately 4.1 MB component table from the saved-scene sweep.

The six patch VTI exports are duplicates for visualization, excluded by
the experiment's .gitignore. They remain available locally and are
regenerated by run_local_patches.py. The original full-domain VTI scene
is also ignored, as it was before these studies. Figures in the reports
are retained in Git; reading the results does not require ParaView or
the ignored scene files.

## Running the software controls

From the repository root, in the rf_explo environment:

~~~powershell
mamba run -n rf_explo python -B -m unittest discover -s experiments/04_margin_tessellation -p "test_*.py" -v
~~~

There are 23 controls across test_saved_sweep.py (7), test_local_films.py
(7), and test_local_patches.py (9). They create their own tiny temporary
scenes and do not need the ignored original VTI files. They cover seed
recovery, interpolation, hidden winners/cavities, digital topology,
volume conventions, sampling, end-to-end outputs, and overwrite guards.

For the publication check, all 23 controls passed together in an isolated
copy of the source tree without the original VTI scene. The component-input
refinement was then repeated from copied patch evidence alone: its CSV
and every saved numerical array matched the retained results exactly.
Git clean-filter checks preserved the bytes of 51 source/result text
files, and 45 documentation links resolved to retained files. This verifies
the packaging in the recorded environment; it does not resolve the open
scientific questions listed below.

## Repeating calculations

Every runner refuses a nonempty output directory. Use a new --output
directory for each repeat; there is no resume mode for these small studies.
The report for each study contains its full commands and interpretation.

The saved-scene sweep, edge audit, and first 3D patch study require
paraview/q32_phi75 with margin.vti, winners.vti, and phase.vti. The edge
and patch runners additionally require field_g1.vti. Automatic patch
selection uses the completed refined edge audit, whereas --patches can
reuse an explicit selection from patches.json. These full scene files
are not supplied by a fresh checkout; do not mistake their absence for
a failure of the mathematical model or of the self-contained tests.

The following repeat uses only the retained patch evidence and generates
new component values at the saved physical locations:

~~~powershell
mamba run -n rf_explo python -B -u experiments/04_margin_tessellation/refine_patch_components.py --source experiments/04_margin_tessellation/results_local_patches --output experiments/04_margin_tessellation/results_local_patch_components_repeat
~~~

It checks exact recovery of the stored coarse component values. It does
not improve the direct reference's sampling resolution or settle its
remaining topology uncertainty.

## Provenance and environment

Each saved study records source/input hashes, numerical parameters,
completion status, and package versions in metadata.json. Absolute paths
describe the producer's workspace; use the CLI --source and --output
arguments when working in another location. They do not require the same
drive letter or username.

The root environment.yml permits a range of dependency versions. For
strict reproduction, use the versions recorded in the relevant metadata:
these studies used Python 3.12.13, NumPy 2.4.3, SciPy 1.17.1,
GSTools 1.7.0, scikit-image 0.26.0, PyVista 0.48.2, and Matplotlib 3.10.9.
This is not a claim of bitwise reproducibility across arbitrary platforms
or later library versions. The exact field-recovery guards detect a
changed realization instead of silently comparing different fields.

The root .gitattributes preserves LF source bytes for the hashed Python
files and disables line-ending conversion in the five recorded result
folders. This prevents a normal Windows/Unix checkout from invalidating
the saved hashes merely by changing line endings. It does not disable
content-change detection: refine_patch_components.py deliberately rejects
changed numerical source files from its parent study. New source changes
should produce a new study and provenance record.

## Open research questions to retain when publishing

- All new measurements use one original realization. The selected patches
  are purposeful cases, not independent trials or an unbiased global sample.
- At 75%, patch 0 and patch 2 retain unresolved digital Euler and
  connectivity differences. Improved volume or phase agreement is not a
  certificate of converged L0.
- Direct finite-grid probes are numerical references, not certified
  continuum geometry. The follow-up keeps that reference fixed.
- No new global L0/L3 convergence result, particle grading calibration,
  or complete margin GMF derivation is claimed.

These limitations are stated in the experiment README and detailed reports.
They are reasons to continue the research, not reasons to withhold a
clearly labelled work-in-progress record of completed calculations.
